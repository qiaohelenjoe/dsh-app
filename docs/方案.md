# DSH 移动端账号平台 —— 总体方案

- 版本: v1.0（2026-10-22）
- 目标: 多用户、多设备、邮箱密码登录，桌面端登录即完成配对，手机端零扫码直接控制电脑上的 DeepSeek Harness
- 部署前提: 自有服务器 + 自有 HTTPS 证书（已具备）

---

## 0. 关键决策速览

| 决策项 | 结论 | 理由 |
|---|---|---|
| 身份模型 | 账号 → 设备 → 会话 三层 | 支持一人多机、一机多端 |
| 登录方式 | 邮箱 + 密码（argon2id） | 用户指定 |
| 桌面端登录 | 浏览器设备授权码（Device Code）流程 | 桌面端不接触密码，标准做法 |
| 手机端登录 | 同账号邮箱密码 | 登录后自动看到全部设备 |
| 配对方式 | **无显式配对**：桌面登录即注册设备 | 用户核心诉求 |
| 跨网通信 | 自建 WSS 反向隧道（HTTP + WebSocket 多路复用） | 桌面端只出站，无需公网 IP/端口映射 |
| 界面共享 | 手机通过隧道加载真实 DSH Web UI | 满足"同一套界面" |
| 第三方依赖 | 无第三方 DSH 插件；只用 Postgres / nginx / Node 标准生态 | 用户要求 |
| 服务端语言 | TypeScript + Fastify + Postgres + ws | 与 DSH 插件同栈，维护成本低 |

---

## 1. 目标与非目标

### 目标

1. **多用户**：任何人可注册；每个账号独立隔离
2. **多设备**：一个账号可绑定多台桌面端、多部手机
3. **零配对**：桌面端登录一次，之后开机自动上线；手机登录后直接看到设备列表
4. **界面共享**：手机看到的就是官方 Web GUI（含同一份会话、工作区、任务）
5. **离线可用**：桌面端只做出站连接，不受 NAT / 防火墙 / 公网 IP 限制
6. **可运营**：设备可撤销、会话可审计、有配额与限流

### 非目标（v1）

- ❌ 第三方 OAuth / 手机验证码登录
- ❌ 端到端加密的 UI 隧道（服务端可见流量，见 §9 安全权衡）
- ❌ 手机端离线运行 / 唤醒离线电脑
- ❌ 计费、订阅、团队协作
- ❌ 移动端专属 UI 重写（v1 复用官方 Web UI）

**三条数据通路**

| 通路 | 用途 |
|---|---|
| `https://域名/v1/*` | 手机/桌面调用 REST API（登录、设备列表） |
| `wss://域名/v1/tunnel` | 桌面插件常驻连接（注册设备、承载隧道） |
| `https://域名/t/<deviceId>/*` | 手机访问指定设备的 DSH Web UI（服务端转发进隧道） |

## 3. 身份模型

### 3.1 三层身份

```
account（人）
  └── device（机器/终端，1:N）
        └── session（一次登录，1:N）
```

| 概念 | 说明 | 关键字段 |
|---|---|---|
| **account** | 用户，邮箱唯一 | `email`, `password_hash`, `status` |
| **device** | 一台具体终端 | `kind`(desktop/mobile), `platform`, `public_key`, `last_seen_at`, `revoked_at` |
| **session** | 一次登录态 | `refresh_token_hash`, `expires_at`, `ip`, `user_agent` |

### 3.2 多设备规则

| 规则 | 值 |
|---|---|
| 单账号桌面端上限 | 20 台 |
| 单账号手机上限 | 10 台 |
| 单设备并发会话 | 5 |
| 设备离线判定 | 心跳超过 90 秒 |
| 设备撤销 | 立即断开隧道 + 删除会话 |

### 3.3 设备密钥

每台设备首次注册时生成并上报：

- **Ed25519 密钥对**：设备身份签名（证明"我是这台设备"）
- **X25519 密钥对**：与手机端协商端到端会话密钥（控制帧加密）

私钥保存在本机安全存储：
- Windows：凭据管理器（DPAPI）
- macOS：Keychain
- 手机：Keychain / Keystore / HUKS

服务端**只存公钥**，被拖库也无法冒充设备。

## 4. 鉴权设计

### 4.1 密码

- 算法：**argon2id**（`m=64MiB, t=3, p=4`）
- 密码策略：≥10 位，不强制复杂度（长度优先），禁止出现在常见泄露字典前 10 万条
- 找回密码：邮件重置链接（需配置 SMTP）；v1 可先提供管理员手动重置

### 4.2 令牌

| 令牌 | 类型 | 有效期 | 存储 |
|---|---|---|---|
| Access Token | JWT (HS256/EdDSA) | 15 分钟 | 客户端内存 |
| Refresh Token | 不透明随机串（32 字节） | 30 天，**轮换** | 服务端存 SHA-256 |
| Device Code | 8 位大写字母数字 | 10 分钟 | 服务端临时表 |
| Tunnel Ticket | 一次性随机串 | 60 秒 | 服务端内存 |

**Refresh 轮换**：每次刷新签发新 refresh 并作废旧 refresh；检测到复用即判定令牌泄露，撤销该会话全部令牌。

### 4.3 桌面端登录流程（Device Code）

```
插件                     浏览器                      服务端
 │  ① POST /v1/auth/device-code                     │
 │ ────────────────────────────────────────────────►│
 │ ◄──────── {user_code:"ABCD-1234", device_code,  │
 │            verification_url:"https://域名/activate"} │
 │  ② 打开浏览器 → 用户在网页里输入 user_code + 登录 │
 │                                                  │
 │  ③ 每 2 秒 POST /v1/auth/device-token {device_code} │
 │ ────────────────────────────────────────────────►│
 │ ◄──────── 202 pending（直到用户在网页确认）       │
 │ ◄──────── 200 {access, refresh, account}         │
 │  ④ POST /v1/devices（登记本机 + 公钥）           │
 │  ⑤ 建立 WSS /v1/tunnel                          │
```

**安全性**：桌面端全程不接触密码；用户代码 10 分钟失效。

### 4.4 手机端登录

```http
POST /v1/auth/login
{ "email": "...", "password": "...", "device": { "name": "iPhone 15", "platform": "ios" } }
→ { "accessToken": "...", "refreshToken": "...", "deviceId": "...", "account": {...} }
```

登录即注册手机设备，`kind=mobile`。

### 4.5 隧道鉴权

桌面端建立 `/v1/tunnel` 时：
1. 用 access token 认证
2. 服务端校验 `device_id` 属于该账号且未撤销
3. 下发一次性 tunnel ticket，之后心跳与转发均绑定该连接

## 5. 数据模型

完整 DDL 见 [schema.sql](./schema.sql)。核心表：

| 表 | 职责 |
|---|---|
| `accounts` | 用户 |
| `email_verifications` | 邮箱验证 / 密码重置令牌 |
| `devices` | 设备（桌面 + 手机） |
| `sessions` | 登录会话（refresh token） |
| `device_codes` | 桌面端设备授权码 |
| `audit_logs` | 登录、设备变更、撤销审计 |
| `rate_limits`（可选） | 限流计数（也可用内存 + Redis） |

关键约束：

- `accounts.email` 唯一（大小写不敏感，存 `citext` 或统一小写）
- `devices.account_id` 级联删除；软删用 `revoked_at`
- 同一账号下 `(account_id, name, kind)` 允许重名，不强制唯一
- `sessions.refresh_token_hash` 唯一索引，防重放

## 7. 隧道协议（自研，替代第三方插件）

### 7.1 连接

```
桌面插件  ──WSS──►  /v1/tunnel    header: Authorization: Bearer <access>
                                  (注册为 device_id)
手机      ──HTTPS──►  /t/<deviceId>/api/...   (由服务端转成隧道帧)
```

### 7.2 帧格式（JSON over WebSocket，二进制正文用 base64）

```jsonc
// 服务端 → 桌面：HTTP 请求
{ "t": "req", "id": "r_001", "method": "GET", "path": "/api/session/list",
  "headers": { "cookie": "<由插件注入的 DSH 凭据>" }, "body": null }

// 桌面 → 服务端：HTTP 响应（可流式分块）
{ "t": "res", "id": "r_001", "status": 200,
  "headers": { "content-type": "application/json" }, "body": "base64...", "more": false }

// 服务端 → 桌面：WebSocket 代理建立
{ "t": "wsopen", "id": "w_001", "path": "/api/remote.mux", "headers": {...} }
// 双向数据
{ "t": "wsdata", "id": "w_001", "data": "base64..." }
{ "t": "wsclose", "id": "w_001", "code": 1000 }

// 心跳
{ "t": "ping" } / { "t": "pong" }
```

### 7.3 关键实现要点

1. **DSH 凭据注入**：插件在进程内启动时，用自己的启动令牌完成一次 `/connect` 交换，拿到 DSH 浏览器 Cookie，缓存后注入每个转发请求（与第三方插件做法一致，但由我们自己实现）。
2. **Host/Origin 处理**：转发到 `127.0.0.1` 时把 `Host` 改写为本机 authority，避免 DSH 的 browser-trust 围栏拒绝。
3. **流式响应**：`more: true` 支持分块，避免大响应占满内存。
4. **背压**：单连接并发请求上限 32；超过则服务端 429。
5. **路径白名单**：只允许 `/api/*`、`/assets/*`、`/` 与静态资源；禁止 `/connect`、`/api/pair/*` 等敏感端点。

## 8. 桌面端插件设计

包名建议：`dsh-mobile-tunnel`（自研，非第三方）

```
apply(ctx):
  ├─ 读取本地凭据（account refresh token；不存在则提示"登录"）
  ├─ 提供 UI 入口：设置页「账号」卡片（登录/登出/设备名/在线状态）
  ├─ 登录成功后：
  │    ├─ 生成 Ed25519/X25519 密钥对 → 安全存储
  │    ├─ POST /v1/devices 注册
  │    └─ 建立 WSS /v1/tunnel（指数退避重连）
  ├─ 收到 req 帧 → fetch 127.0.0.1:<dshPort><path>（带缓存 Cookie）→ 回 res 帧
  ├─ 收到 wsopen → 用 ws 库连本机 → 双向转发
  └─ 监听 DSH 生命周期：退出时发送 offline，由服务端立即标记离线
```

**冷启动行为**：开机后插件用 refresh token 静默恢复，**无需用户操作**。

**多实例保护**：同一 device_id 只允许一条隧道；新连接建立时踢掉旧连接。

## 9. 移动端设计

### 9.1 v1（最快可用）

- 原生壳（Flutter）内置 WebView，加载 `https://域名/t/<deviceId>/`
- 首次打开：登录页（邮箱密码）→ 设备列表（在线/离线、平台图标）→ 点设备进入
- Cookie 持久化，下次启动直连最近设备
- 扫码兜底：桌面设置页仍展示二维码（内容为 `https://域名/t/<deviceId>/`），便于新设备快速进入

### 9.2 移动适配（P3）

由于不依赖第三方插件，**竖屏适配层需要自研**：

- 方案：自研 DSH 客户端插件（`dsh-mobile-adapt`），注入 `@media (max-width: 768px)` 样式与触控手势
- 工作量：2–4 周（第三方插件同类代码约 69KB）
- v1 可先接受桌面布局缩放

## 10. 部署方案

### 10.1 组件

| 组件 | 版本 | 说明 |
|---|---|---|
| nginx | 1.28+ | TLS 终止、反向代理、WebSocket 升级 |
| Node.js | 22 LTS | API 服务运行时 |
| PostgreSQL | 16 | 数据存储 |
| systemd | — | 进程守护、开机自启 |

### 10.2 nginx 关键配置

```nginx
# 桌面隧道（WebSocket 长连接）
location /v1/tunnel {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;      # 长连接不超时
    proxy_send_timeout 3600s;
}

# 设备 UI 代理（普通 HTTP）
location /t/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;            # 流式
    proxy_read_timeout 300s;
}

# REST API
location /v1/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## 11. 安全与合规

| 项 | 措施 |
|---|---|
| 传输 | 全站 TLS 1.2+，HSTS |
| 密码存储 | argon2id + 每用户独立 salt |
| 令牌 | 短 access + 轮换 refresh + 复用检测 |
| 设备 | Ed25519 公钥；撤销即断连 |
| 隧道 | 一次性 ticket；路径白名单；并发上限 |
| 注入 | 所有 SQL 走参数化；输入 zod 校验 |
| 限流 | 登录 5 次/分钟/IP；注册 3 次/小时/IP；隧道 10 次/分钟/设备 |
| 审计 | 登录成功/失败、设备注册/撤销、令牌复用全部落 `audit_logs` |
| 隐私 | 不存储 DSH 会话内容；不存储 DeepSeek 凭据 |
| **权衡** | UI 隧道由服务端 TLS 终止，**服务器可见流量**（与第三方插件的中继同性质）。若要求端到端，需另做 P2P 方案，v1 不做 |

## 13. 验收标准

1. 用户 A 注册后，桌面端用设备码登录，设备自动出现在手机端列表，**全程无需扫码**
2. 用户 A 与用户 B 的数据完全隔离（A 的令牌访问不到 B 的设备）
3. 同一账号下 3 台桌面 + 2 部手机可同时在线
4. 手机点设备后 3 秒内加载出 DSH Web UI
5. 重启桌面电脑，插件自动上线，手机端状态 30 秒内变回在线
6. 撤销某设备后，该设备隧道立即断开，令牌立即失效
7. 弱网（200ms RTT + 5% 丢包）下 WebSocket 不中断，断线 30 秒内自动恢复
8. 登录接口暴力尝试 10 次被限流
9. 服务端重启后，所有客户端自动重连
10. 数据库备份可完整还原

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| DSH 升级导致插件 API 变化 | 插件失效 | 适配层收敛到单文件；锁 DSH 版本；升级前跑集成测试 |
| 隧道实现复杂（HTTP 分块、WS 代理） | 进度超期 | 先只做 HTTP，WS 单列一个里程碑；用并发上限简化背压 |
| DSH 内部 Cookie 注入方式随版本改变 | 代理 401 | 启动时探测；失败降级为提示用户 |
| 多用户滥用（注册机、刷接口） | 资源耗尽 | 限流 + 邮箱验证 + 设备配额 |
| 证书/域名到期 | 全站不可用 | 到期提醒；自动续期（acme.sh/certbot） |
| 服务端被入侵 | 设备公钥泄露（无密码泄露） | 公钥不可逆；敏感数据最小化；审计日志外送 |

---

## 15. 待你确认

1. **服务器选哪台？** 生产服务器？需要能跑 Postgres + Node，且域名解析到它
2. **域名用哪个？** 例如 `dsh.hbzxht.com`（你已有泛域名证书）
3. **注册是否开放？** 建议：开放注册 + 邮箱验证；或先邀请制（管理后台发码）
4. **是否现在就停用第三方插件？** `cordis.patch.yml` 里 `remote-web-ui` 那条要移除，避免两套系统抢入口
5. **手机端 v1 是否接受桌面布局？** 接受则 5 周交付，否则 7–9 周
